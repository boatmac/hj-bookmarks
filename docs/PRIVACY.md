# HJ Bookmarks 隐私与数据边界

本文说明 HJ Bookmarks 在浏览器、本地目录和远端同步服务之间保存或传输哪些信息。项目是纯静态应用，没有由维护者运营的账号系统、业务后端、遥测服务或书签数据库。

## 数据流概览

| 位置 | 保存内容 | 不应包含 |
| --- | --- | --- |
| IndexedDB | 书签、文件夹、回收站、同步基线、冲突、设备标识与显示名称、不含查询参数的同步地址、WebDAV/Koofr 用户名、非敏感设置 | WebDAV 密码、Azure SAS Token、同步加密口令、备份加密口令 |
| `sessionStorage` | 仅在用户明确选择后，临时保存当前标签页刷新所需的密码、SAS Token 和口令 | 普通重新打开或跨会话恢复的凭据 |
| `localStorage` | 主题、语言、排序、多标签页协调事件（可能包含用户设置的设备显示名称）、远端版本摘要和仅用于比较的端点摘要 | 原始同步地址、用户名、密码、口令、书签内容 |
| 自动备份目录 | 用户选择的明文或 AES-GCM 加密书签快照 | 同步地址、WebDAV/Koofr 凭据、Azure SAS Token、同步口令 |
| 手动 JSON / HTML 导出 | 用户主动导出的书签与文件夹；JSON 是明文完整数据 | 同步设置和所有凭据 |
| WebDAV / Azure Blob / 本地同步目录 | AES-GCM 加密信封、必要的格式和密码学参数 | 明文书签、设备名称、密码、SAS Token、加密口令、同步地址 |
| 静态托管平台 | HTML、CSS、JavaScript、公开文档和测试 | 用户书签、浏览器数据库和同步配置 |

## 浏览器本地存储

同步必须在本机记住目标位置，因此不含秘密查询参数的同步地址和 WebDAV/Koofr 用户名会保存在当前 Origin 的 IndexedDB 中。它们不会进入手动导出、自动书签备份或远端加密文件。密码、Azure SAS Token 和加密口令默认只存在当前页面内存。完整 Azure 数据边界见 [`AZURE-BLOB.md`](AZURE-BLOB.md)。

只有用户明确启用“刷新时保留凭据”后，凭据才会进入当前标签页的 `sessionStorage`。应用仅在 Navigation Timing 明确表示真正刷新时恢复；普通新开页面、关闭后重开、历史会话恢复和 BFCache 返回都会清除。

自动备份目录和本地同步目录使用浏览器管理的 File System Access 句柄。句柄是否能在浏览器重启后继续授权由浏览器决定；网页不会获得或上传操作系统完整路径。

## 网络与远端服务

远端同步请求从浏览器直接发送到用户填写的 WebDAV、Azure Blob 或兼容服务，不经过 HJ Bookmarks 维护者的服务器。浏览器开发者工具和同步服务自身仍能看到请求目标、账号以及网络元数据；客户端加密不隐藏流量发生时间、密文大小或远端文件名。

上传前，书签、回收站快照和设备名称在本机使用 PBKDF2-SHA-256 派生密钥，并由 AES-256-GCM 加密。远端文件包含 salt、IV、迭代次数和密文，但不包含密码、SAS Token 或加密口令。项目维护者无法恢复遗失的口令。

## 备份和导出

自动本地备份默认是明文 JSON，除非用户主动启用备份加密。即使使用加密，文件名仍可能显示快照时间。手动点击“导出 JSON 备份”始终生成明文迁移文件，应像其他私人数据一样保管。

恢复前紧急备份必须成功写入后，应用才会修改 IndexedDB。当前备份设置或所选快照要求加密时，紧急备份也会加密。

## 日志与错误

生产代码不得把原始 `Error` 对象直接传给控制台。日志只保留经过过滤的错误名称、通用消息、内部错误码和 HTTP 状态；URL、认证头、常见本机用户目录、远端路径、错误堆栈、`cause` 和自定义请求目标都会被删除或替换。

公开 Issue、截图和诊断信息仍需由提交者检查并脱敏。不要提交设置窗口、网络请求详情、真实远端目录、Authorization、Cookie、令牌、密码或加密口令。

## 公开内容发布保护

`scripts/audit-public-content.mjs` 会在提交、推送、CI、Pages 和便携包发布前检查：

- Basic/Bearer 认证头和常见访问令牌；
- 私钥材料、URL 内嵌凭据和秘密查询参数；
- 用户目录、私有网络地址和非示例 WebDAV / Azure Blob 地址；
- Koofr 通用根地址之外未经 `Example-*` 标记的目录；
- 未经安全包装的生产控制台错误输出；
- 便携包中不应出现的维护文件。

审计输出只报告规则和文件位置，不回显匹配值。GitHub Secret Scanning 与 Push Protection 作为额外防线。脚本会检查图片等二进制文件中的可打印元数据，但不会对像素内容执行 OCR；它也不能识别所有私人名称，因此提交前仍必须人工检查暂存差异和截图。
